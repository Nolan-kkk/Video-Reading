# 平台获取：B站与抖音

接受标准 `https://www.bilibili.com/video/BV.../` / `av...`、
`https://www.douyin.com/video/<数字ID>`，以及官方 `b23.tv/<短码>`、
`v.douyin.com/<短码>`。B站移动站规范化到 www；保留单个 `p=`，移除分享追踪参数。
短链解析必须访问网络；只允许 HTTPS、相应固定域名和可信的视频路径，最多三次重定向。
不支持番剧、合集、直播、Cookie/浏览器登录，也不绕过访问控制。

`fetch URL --dry-run` 联网查询公开元数据和字幕语言，不下载视频、不调用 AI。
`fetch URL` 下载；`analyze URL` 下载后复用本地处理流水线；默认不调用 AI。
云端 URL 实际执行会先验证用户 Key、预算及费用授权，避免无效配置先下载大文件。

依赖官方 [yt-dlp 项目](https://github.com/yt-dlp/yt-dlp)，当前验证版为 2026.10.26。
它的抖音提取器在平台限制下可能无法匿名获取；本次多个公开样例及用户授权样例均遭遇限制。
支持链接输入和安全失败不意味着媒体已能成功下载；此路径仍需真实视频成功验收。
正常字幕与自动字幕均可选，排除 danmaku；只接受 SRT/VTT 轨道，统一保存 captions.srt。
`--subtitle-language` 精确选择；不指定时优先中文，其次英文，再选其他可用语言。
不能保证平台所有字幕在未登录时可访问，也不能仅从返回分类判断其是否人工制作，
因此原始证据会记录“平台字幕可能为自动生成、未人工核验”。

字幕是可下载的时间戳轨道。烧录在画面中的文字需要视觉/OCR，弹幕不是语音字幕。
没有字幕的带音轨视频可显式启用 --transcribe 本地转录；--ocr 提取采样帧中的烧录文字。
云端理解前仍要求字幕或转录文本；显式 --visual-only 才接受缺失语音。

## 本地文件与状态

下载缓存默认位于 `.cache/downloads/bilibili_<id>/` 或 `douyin_<id>/`：source.mkv、可用时的 captions.srt，
以及 source.json。文件名固定，不使用远程标题作为路径。source.json 只保存公开来源、
规范化 URL、语言、状态和安全错误，不包含原始 SDK 响应、签名 CDN URL 或 Cookie。
失败保留状态和部分文件，不静默清理；用户自行管理缓存，暂不自动续跑或复用。
Markdown 输出复制必要证据图片，不分发原视频；本项目也不把测试视频纳入 Git/安装包。

默认 720p、1024 MiB、600 秒；体积检查在下载进度回调执行，可能多出一个缓冲块，
合并临时副本需要额外空间。未发现有限时长、直播、超长视频先阻止下载。网络错误不自动重试。

## 已知验证范围

用户提供的 BV1NNNqzVEi4 已在 2026-11-04 实际获取：平台时长 32.621 秒，
转封装后探测 32.601 秒。当前公开请求没有独立字幕；不据此断言平台/画面本身无字幕。
已验证下载、音轨、7 张跨全片关键帧及限制标记；后续用实际本地模型得到 17 段语音和
7 帧 OCR 结果，没有调用付费 API。见 [本地识别](local-recognition.md)。
平台字幕成功获取和对齐只经过离线契约测试，仍需公开可访问字幕的真实样例验收。

用户提供的抖音分享短链已实测转换为标准视频地址，但匿名元数据获取失败。
同版本 yt-dlp 的诊断指向 Cookie 或平台访问限制；没有下载视频或调用 AI。
没有读取浏览器账户，也不能据此断言视频本身不存在或用户无权访问。
处理有权使用的已下载本地视频仍可使用现有字幕、语音转录和 OCR 流程。
